## 구현 상세

### CheckpointerManager 패턴

```python
# backend/app/octostrator/checkpointer/postgres_checkpointer.py

class CheckpointerManager:
    """AsyncPostgresSaver 연결 생명주기 관리"""

    async def create_checkpointer(self, conn_string: Optional[str] = None) -> AsyncPostgresSaver:
        # AsyncPostgresSaver.from_conn_string()은 async context manager 반환
        context_manager = AsyncPostgresSaver.from_conn_string(conn_string)

        # Context manager에 진입
        actual_checkpointer = await context_manager.__aenter__()

        # PostgreSQL 테이블 자동 생성
        await actual_checkpointer.setup()  # ← 4개 테이블 자동 생성

        # checkpointer와 context manager를 모두 캐싱 (연결 유지)
        self._checkpointers[conn_string] = actual_checkpointer
        self._context_managers[conn_string] = context_manager

        return actual_checkpointer
```

**중요 사항**:
- ⚠️ Context manager를 캐싱하지 않으면 연결이 즉시 닫힘
- ⚠️ `.setup()` 호출 시 자동으로 4개 테이블 생성됨
- ⚠️ 테이블은 하드코딩되어 있으며 사용자가 수정 불가능

### SessionManager 통합

```python
# backend/app/octostrator/session/session_manager.py

class SessionManager:
    """thread_id 기반 세션 생성 및 관리"""

    def create_session(self, user_id: Optional[str] = None) -> str:
        # UUID 기반 thread_id 생성
        thread_id = f"thread_{uuid.uuid4().hex[:16]}"

        session_data = {
            "thread_id": thread_id,
            "user_id": user_id,  # ← user_id와 thread_id 매핑
            "created_at": datetime.now().isoformat(),
            "status": "active"
        }

        self._sessions[thread_id] = session_data
        return thread_id
```

**thread_id와 user_id 관계**:
- SessionManager가 메모리에서 매핑 관리
- LangGraph checkpoints 테이블의 `thread_id`로 세션 식별
- `metadata` JSONB 필드에 user_id 저장 가능

## 테이블별 용도

### 1. checkpoint_migrations
- **용도**: DB 마이그레이션 버전 추적
- **데이터 예시**:
  ```
  v
  ---
  1
  2
  3
  ```

### 2. checkpoints
- **용도**: Graph 실행 상태 저장
- **데이터 예시**:
  ```json
  {
    "thread_id": "thread_a1b2c3d4e5f6g7h8",
    "checkpoint_ns": "",
    "checkpoint_id": "1ef9a...cbd4",
    "parent_checkpoint_id": "1ef9a...abc3",
    "checkpoint": {
      "v": 1,
      "ts": "2025-11-10T10:30:00Z",
      "channel_values": {
        "messages": ["..."],
        "next": "program_designer"
      }
    },
    "metadata": {
      "user_id": "123",
      "step": 5,
      "writes": {...}
    }
  }
  ```

### 3. checkpoint_blobs
- **용도**: 채널별 값 버저닝 (최적화)
- **데이터 예시**:
  ```
  thread_id              | channel   | version | blob
  -----------------------|-----------|---------|------
  thread_a1b2c3d4e5f6g7h8| messages  | v1      | 0x89504e47...
  thread_a1b2c3d4e5f6g7h8| messages  | v2      | 0x89504e48...
  ```
- **최적화 원리**: 변경된 채널만 새 버전으로 저장

### 4. checkpoint_writes
- **용도**: Pending writes 저장 (에러 복구)
- **데이터 예시**:
  ```
  checkpoint_id | task_id        | idx | channel  | blob
  --------------|----------------|-----|----------|------
  1ef9a...cbd4  | program_design | 0   | next     | 0x...
  1ef9a...cbd4  | program_design | 1   | messages | 0x...
  ```
- **에러 복구 원리**: 노드 실패 시 성공한 노드의 writes만 재적용

## 데이터 관리

### ⚠️ 자동 정리 없음
- LangGraph는 오래된 체크포인트를 자동으로 삭제하지 않음
- 운영 환경에서는 주기적인 정리 스크립트 필요

### 수동 정리 예시
```sql
-- 30일 이상 된 체크포인트 삭제
DELETE FROM checkpoints
WHERE (metadata->>'created_at')::timestamp < NOW() - INTERVAL '30 days';

-- 고아 blobs 삭제
DELETE FROM checkpoint_blobs
WHERE (thread_id, checkpoint_ns) NOT IN (
    SELECT thread_id, checkpoint_ns FROM checkpoints
);

-- 고아 writes 삭제
DELETE FROM checkpoint_writes
WHERE (thread_id, checkpoint_ns, checkpoint_id) NOT IN (
    SELECT thread_id, checkpoint_ns, checkpoint_id FROM checkpoints
);
```
