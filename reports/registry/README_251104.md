## 🔑 핵심 결론

### ❌ 명시적 싱글톤 Registry 구현 불필요

**이유**:
1. **LangGraph가 이미 Node Registry 제공**
   - `workflow.add_node(name, func)` 방식
   - Command 기반 동적 라우팅 (`goto=name`)

2. **Stateless 함수형 설계**
   - 모든 Agent는 순수 함수
   - 상태는 SupervisorState에만 저장
   - 싱글톤으로 상태 관리할 필요 없음

3. **복잡도 증가**
   - 싱글톤 Registry: 100줄 이상
   - 단순 Dict: 10줄
   - Thread-safe, Lock, 메타클래스 등 불필요

### ✅ 대신 구현할 것

**Tools Registry** (단순 Dict)
```python
# tools/__init__.py

TOOLS = {
    "vector_search": vector_search_tool,
    "db_query": db_query_tool,
    "llm_call": llm_call_tool,
}

def get_tool(name: str):
    return TOOLS[name]
```

**SubGraphs Registry** (단순 Dict)
```python
# sub_graphs/__init__.py

SUBGRAPHS = {
    "rag": build_rag_subgraph,
    "validation": build_validation_subgraph,
}

def get_subgraph(name: str):
    return SUBGRAPHS[name]()  # 빌더 함수 호출
```

## ❓ FAQ

### Q1: 왜 싱글톤 Registry를 구현하지 않나요?
**A**: LangGraph가 이미 Node Registry를 제공하며, Command 기반 라우팅이 더 유연하고 효율적입니다. 싱글톤 패턴은 Stateless 함수형 설계에 맞지 않으며, 불필요한 복잡도를 증가시킵니다.

### Q2: Tools는 어떻게 등록하나요?
**A**: 단순 Dict를 사용합니다. `tools/__init__.py`에 `TOOLS = {"name": function}` 형태로 등록하고, `get_tool(name)`으로 가져옵니다.

### Q3: Agent는 어떻게 Tools를 사용하나요?
**A**:
```python
from backend.app.octostrator.tools import get_tool

async def agent_node(state):
    db_query = get_tool("db_query")
    results = await db_query(table="users")
```

### Q4: SubGraph는 언제 사용하나요?
**A**: 여러 Agent가 공유하는 복잡한 로직(검색 + 요약, 검증 + 정규화 등)을 SubGraph로 분리합니다.

### Q5: 기존 Mock Agent는 어떻게 변경하나요?
**A**: Phase 3에서 DB 직접 접근을 Tools 사용으로 변경합니다. 마이그레이션 가이드는 REGISTRY_IMPLEMENTATION_PLAN_251104.md의 섹션 8을 참고하세요.
