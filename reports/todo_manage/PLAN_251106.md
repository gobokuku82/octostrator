## 🎯 프로젝트 개요

### 프로젝트 목적

사용자가 **Agent의 자율적 실행을 관찰하고 언제든 개입할 수 있는** 동적 Todo 관리 시스템 구축

### 핵심 가치

1. **Agent 자율성**: Agent가 막힐 때까지 자율적으로 작업 수행
2. **사용자 제어권**: 언제든 계획/Todo/Agent를 확인하고 수정 가능
3. **투명한 추적**: 모든 작업 내역을 타임스탬프와 함께 기록
4. **유연한 개입**: 사용자가 원하는 시점에 중단/수정/재개 가능

## 📊 현재 상태 분석

### 현재 구현된 기능

#### ✅ 이미 작동하는 것

1. **3-Layer + Supervisor 아키텍처**
   - Supervisor (Octostrator): 전체 흐름 제어
   - Cognitive Layer: 계획 생성
   - Execute Layer: Agent 실행
   - Response Layer: 결과 생성
   - Todo Manager: **조건부 실행** (필요시에만 호출)

2. **기본 HITL (Human-in-the-Loop)**
   - `requires_approval` 플래그로 중단
   - `/api/sessions/{thread_id}/resume` 엔드포인트로 재개

3. **PostgreSQL Checkpointing**
   - 모든 State 변경사항 저장
   - 세션 복원 가능

4. **WebSocket 실시간 스트리밍**
   - Layer별 진행 상황 전송
   - Plan/Todos/Execution 결과 업데이트

#### ❌ 현재 부족한 것

1. **State History 추적**
   - 현재: State가 덮어쓰기됨
   - 필요: 모든 변경사항을 히스토리로 보관

2. **Todo 동적 관리**
   - 현재: Todo가 한 번 생성되면 수정 불가
   - 필요: 사용자가 언제든 Todo 추가/삭제/수정

3. **Agent 선택/변경**
   - 현재: Todo에 Agent가 자동 할당
   - 필요: 사용자가 Agent 선택/변경 가능

4. **작업 내역 조회**
   - 현재: 현재 State만 조회 가능
   - 필요: "4번 작업이 뭐였지?" 같은 질문에 답변

5. **사용자 중단 기능**
   - 현재: Agent가 `requires_approval`을 설정해야만 중단
   - 필요: 사용자가 언제든 "중단" 버튼으로 멈춤

### 기능 요구사항 (Functional Requirements)

#### FR-1: State History 관리
- **FR-1.1**: 모든 작업을 타임스탬프와 함께 기록
- **FR-1.2**: 작업 내역을 단계별(step)로 조회 가능
- **FR-1.3**: Plan 변경 히스토리 보관
- **FR-1.4**: 사용자 개입 내역 기록

#### FR-2: Todo 동적 관리
- **FR-2.1**: Todo 추가 (런타임)
- **FR-2.2**: Todo 삭제
- **FR-2.3**: Todo 순서 변경
- **FR-2.4**: Todo 상태 수정 (pending → completed 등)
- **FR-2.5**: 변경 내역 자동 기록

#### FR-3: Agent 관리
- **FR-3.1**: Todo에 할당된 Agent 변경
- **FR-3.2**: 사용 가능한 Agent 목록 조회
- **FR-3.3**: Agent 기본 정보 조회 (capabilities, description)

#### FR-4: 실행 제어
- **FR-4.1**: 사용자가 언제든 실행 중단
- **FR-4.2**: 중단된 세션 재개
- **FR-4.3**: 특정 Todo부터 재실행
- **FR-4.4**: 실패한 Todo 재시도

#### FR-5: 조회 API
- **FR-5.1**: 전체 작업 내역 조회
- **FR-5.2**: 특정 Step의 작업 조회
- **FR-5.3**: Plan 히스토리 조회
- **FR-5.4**: 사용자 개입 내역 조회
- **FR-5.5**: 현재 진행 상황 요약

### 비기능 요구사항 (Non-Functional Requirements)

#### NFR-1: 성능
- State 조회는 1초 이내 응답
- Todo 수정 반영은 즉시 (200ms 이내)

#### NFR-2: 확장성
- History는 최대 1000개 항목까지 저장
- 오래된 항목은 자동 아카이빙

#### NFR-3: 안정성
- State 수정 시 원자성 보장
- 중단 중에도 State 일관성 유지

#### NFR-4: 사용성
- API 응답은 명확한 에러 메시지 포함
- History 조회는 페이지네이션 지원

## 🏛️ 전체 아키텍처

### 그래프 구조 (신규 설계)

**핵심 원칙**: Supervisor가 모든 것을 제어하며, **Todo Manager는 필요시에만 호출**

```
START
  ↓
Supervisor (Octostrator)
  ↓
Cognitive Layer (계획 생성)
  ↓
[조건 판단: Todo Manager 필요?]
  ↓ YES                            ↓ NO
Todo Manager                   Execute Layer
  ↓                                 ↓
Execute Layer                  Response Layer
  ↓                                 ↓
Response Layer                     END
  ↓
END
```

#### Todo Manager 호출 조건

Todo Manager는 다음 경우에만 실행됩니다:

1. **Cognitive Layer가 요청**: `plan_requires_todos = True`
   - 예: 복잡한 계획으로 Todo 분할 필요
2. **Execute Layer가 요청**: `need_todo_update = True`
   - 예: 실행 중 추가 작업 발견
3. **사용자가 직접 API 호출**: `PUT /todos`, `POST /todos`
   - 사용자가 언제든 Todo 수정 가능

#### 중요: Todos는 항상 존재

- `state["todos"]`는 항상 State에 존재 (초기값: `[]`)
- Todo Manager **노드 실행**과 **todos 데이터 존재**는 별개
- 사용자는 API로 언제든 `todos` 수정 가능

#### Conditional Edge 로직

```python
def should_use_todo_manager(state: OctostratorState) -> str:
    """Cognitive → Execute 사이의 분기 결정"""

    # Cognitive가 Todo 생성 요청
    if state.get("plan_requires_todos", False):
        return "todo"

    # 사용자가 API로 Todo 수정 요청
    if state.get("user_requested_todo_update", False):
        return "todo"

    # 기본: Todo Manager 건너뛰기
    return "execute"
```

### 개선된 State 구조

```python

  # 신규 추가: Todo Manager 제어

}
```

## ⚠️ 위험 요소 및 대응

### 위험 1: History 데이터 크기 증가
**영향**: PostgreSQL 부하, 조회 성능 저하
**확률**: 높음
**대응책**:
- History 최대 항목 수 제한 (1000개)
- 오래된 항목 자동 아카이빙
- 페이지네이션 구현

### 위험 2: State 수정 시 동시성 문제
**영향**: State 불일치, 데이터 손실
**확률**: 중간
**대응책**:
- LangGraph의 update_state는 원자성 보장
- 낙관적 잠금(Optimistic Locking) 사용
- 버전 관리 (plan_version, todos_version)

### 위험 3: API 복잡도 증가
**영향**: 유지보수 어려움
**확률**: 중간
**대응책**:
- API 문서 자동 생성 (FastAPI Swagger)
- 명확한 에러 메시지
- 테스트 커버리지 80% 이상
